## 任務 1：新聞摘要過濾

### 1. 任務目標
每日掃描台股相關新聞，過濾情緒性用字，找出有事實根據的機會信號，並讓多則新聞互相印證。

### 2. 觸發方式
- **Cron**：每日 07:30 Taiwan Time（盤前準備）
- 失敗不重試（早餐新聞非關鍵）

### 3. 資料來源
| 來源 | 用途 | 頻率 |
|------|------|------|
| Brave Search | 一般新聞關鍵字搜尋 | 每日 |
| Tavily Search | 需要 AI 摘要的深度研究 | 必要時 |
| TWSE/Tpex 重大公告 | 盤後官方新聞 | 每日 |

**關鍵字策略（避免情緒性標題）：**
- 正面：擴廠、資本支出上修、取得重大合約、策略合作、新產線、量產、導入客戶、獲利超標
- 負面：裁員、停工、火災、客戶終止、違約、解任、辭職
- 產業：原物料報價、景氣燈號、進出口數據、產能利用率

### 4. 處理邏輯
```
Step 1: 搜尋當日台股相關新聞（ Brave Search，關鍵字組合）
Step 2: 過濾情緒性用字（標題含「爆」、「噴」、「暴跌」等不處理）
Step 3: 找出事實性描述（數字、百分比、具體事件）
Step 4: 多來源印證（同一件事是否有 ≥2 個獨立來源確認）
Step 5: 寫入 Notion 新聞日誌
Step 6: 有高信心機會時發送 Telegram 早報
```

### 5. Notion 輸出格式
**資料庫**：news_log（新建）
| 欄位 | 類型 | 說明 |
|------|------|------|
| 日期 | Date | 新聞發布日期 |
| 股票代碼 | Text | 相關個股（多選） |
| 標題 | Title | 新聞標題 |
| 摘要 | Text | 1-2 句話描述 |
| 來源 | Text | 新聞來源 |
| 訊號等級 | Select | 高/中/低 |
| 多源印證 | Checkbox | 是否 ≥2 來源 |
| 事實標記 | Text | 提取的具體數字 |
| 推測標記 | Text | 標註「推測」部分 |

### 6. Telegram 通知條件
- 發送早報：每日 07:45（Taipei Time）
- 內容：最多 5 則高信心機會，每則附來來源
- 無高信心機會時：發送「今日無顯著新信號」
- 緊急：重大負面事件（火災、解任等）立即發送

### 7. 與其他任務的介面
- **輸入**：Task 5 追蹤清單中的個股相關新聞優先處理
- **輸出**：發現新機會時更新 Task 5 追蹤狀態

### 8. 依賴與順序
- 不依賴其他任務，可獨立執行
- Task 5（追蹤清單）可參考本任務輸出

### 9. 預期產出
- Notion news_log 每日 10-30 筆新聞
- Telegram 早報 1 則（含 0-5 則精選）

### 10. 紅線限制
- 🚫 不處理 PDF 格式新聞
- 🚫 推測必須標註，不得當事實輸出
- 🚫 情緒性標題不納入分析（只篩選事實）

## 任務 5：追蹤清單維護

### 1. 任務目標
維護 Kai 的個股追蹤清單與狀態，並記錄交易紀錄。

### 2. 觸發方式
- **手動**：Kai 直接對話說「我要追蹤這檔」
- **自動**：Task 1/2/3/4 發現新機會時自動建議
- **每日**：與 Task 2 同時執行（18:00），更新所有狀態

### 3. 資料來源
| 來源 | 用途 |
|------|------|
| Kai 直接輸入 | 新增/移除追蹤 |
| Task 1 新聞 | 宏觀變化信號 |
| Task 2 營收 | 營收異常 |
| Task 3 報告發佈 | 新事件 |
| Task 4 券商報告 | 目標價/評等變化 |
| Task 6 研究報告 | 結論更新 |

### 4. 處理邏輯
```
【新增追蹤】
Step 1: Kai 說「我要追蹤XXXX」
Step 2: 建立新頁面，狀態 = pending
Step 3: 回報「已加入追蹤，狀態 pending」

【狀態更新】
Step 1: 收到其他任務的信號
Step 2: 評估是否足以推動狀態轉換
Step 3: 更新狀態並記錄更新原因

【狀態定義】
pending（初步觀察）
  → active：Task 2 營收 YoY>10% 或 有实质变化 thesis
  → excluded：被反證

active（正式立案）
  → validated：Task 2 關鍵指標連續 2 季達標
  → excluded：本質假設被反證

validated（驗證達標）
  → downgraded：強度下降（無新支撐 >30 天）
  → completed：已達目標或 thesis 失效

downgraded（強度下降）
  → excluded：確認失敗
  → validated：重新出現支撐信號

【交易紀錄】
- entry：進場日期、價格、理由（來自哪個 thesis）
- exit：出場日期、價格、理由（thesis 實現/失效）
```

### 1. 任務目標
將 Kai 的策略想法翻譯成 Python 程式，用 yfinance 歷史資料回測，給出績效數據。

### 2. 觸發方式
- **手動**：Kai 說「幫我回測這個策略...」並描述策略

### 3. 資料來源
| 來源 | 用途 |
|------|------|
| yfinance | 台股歷史價格資料 |
| FinMind | 營收、財報等基本面數據（必要時） |

### 4. 處理邏輯
```
Step 1: Kai 描述策略
Step 2: 翻譯成 Python 程式：
  - 明確進場條件（技術指標/基本面篩選）
  - 明確出場條件（停損/停利/時間）
  - 定義回測期間
Step 3: 用 yfinance 抓取歷史資料
Step 4: 執行回測
Step 5: 計算績效指標：
  - 總報酬率
  - 年化報酬率
  - 夏普比率（Sharpe Ratio）
  - 最大回檔（Max Drawdown）
  - 勝率
  - 平均持有天數
Step 6: 參數掃描（如有必要）
Step 7: 寫入 Notion backtest_results
Step 8: 發送 Telegram 摘要
```

### 5. Notion 輸出格式
**資料庫**：backtest_results（新建）
| 欄位 | 類型 | 說明 |
|------|------|------|
| 策略名稱 | Title | Kai 給的策略名稱 |
| 回測日期 | Date | 回測執行日期 |
| 回測期間 | Text | 起訖年月 |
| 總報酬率 | Number | % |
| 年化報酬率 | Number | % |
| 夏普比率 | Number |  |
| 最大回檔 | Number | % |
| 勝率 | Number | % |
| 平均持有天數 | Number | 天 |
| 交易次數 | Number | 筆 |
| 策略描述 | Text | 完整策略邏輯 |
| Python 程式碼 | Text | 可複製的程式 |
| 最佳參數 | Text | 參數掃描結果 |
| 備註 | Text | 其他 |

### 6. Telegram 通知條件
- **回測完成時**：發送績效摘要（總報酬、年化報酬、夏普比率、最大回檔）
- 格式：`策略：XXX | 總報酬：XX% | 年化：XX% | 夏普：X.XX | 最大回檔：XX%`

### 7. 與其他任務的介面
- **Task 5**：交易策略可基於追蹤清單中的股票
- 可與 Task 6 連結：研究報告可引用回測結果

### 8. 依賴與順序
- 完全獨立，Kai 隨時可觸發
- yfinance 不受限於 TWSE/Tpex 速率限制

### 9. 預期產出
- Notion backtest_results：每次回測一筆
- Telegram 摘要：每次 1 則

### 10. 紅線限制
- 🚫 回測結果不代表未來績效，必須標註「歷史績效不代表未來」
- 🚫 不提供具體買賣建議，只呈現數據
- 🚫 策略邏輯必須由 Kai 提供，不代為發明
