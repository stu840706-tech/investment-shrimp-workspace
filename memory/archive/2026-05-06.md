### 背景：新聞管線日期錯位問題（已存在，2026-05-06 23:00 cron 確認）

 cron 在 UTC 23:00（Taipei 07:00）執行，但使用 **UTC 日期**（`datetime.now().strftime("%Y%m%d")` = `20260506`）寫入檔案，而非台北日期（應為 `20260507`）。

**錯位鏈：**
```
cron UTC 23:00 執行
  → news_pipeline.py utc_date = datetime.now().strftime("%Y%m%d") = "20260506"
  → news_aggregator.py → 寫入 processed-20260506-07.jsonl（應為 20260507-07）
  → news_publisher.py → 讀取 processed-20260506-07.jsonl ✓ 成功
  → sent_state 標記 "2026-05-06-AM": true ✓ 正確
```

**問題：**
- processed 檔案日期落後台北日期一天
- 2026-05-07 07:45 的 cron 嘗試找 `processed-20260507-07.jsonl`，但上一個 cron 產出的是 `processed-20260506-07.jsonl`
- 因 `sent_state` 已標記 `2026-05-06-AM: true`，**被 skip**，沒有多餘消耗

### 根本原因
`news_pipeline.py` 行 82：`utc_date = datetime.now().strftime("%Y%m%d")`（UTC 日期）
應改為計算台北日期或由 pipeline 直接計算並傳入。
